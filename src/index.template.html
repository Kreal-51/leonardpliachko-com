// How I work

How a feature moves through my hands

Most of the cost of a feature is decided before the first line of production code, so that is where I spend my time.

  1. Hear it

    Requests from customers, sales and support land in one pool, with the real problem written next to them.

  2. Click it

    A working prototype in a day or two. People react to a screen, not a paragraph.

  3. Cut it

    Scope down to what solves the problem. User stories the team can estimate.

  4. Ship it

    Sprint, QA, release. I stay in the details with engineering until it is live.

  5. Tell it

    A release post for the whole company, a Q&A for sales and support, and credit to whoever asked.
